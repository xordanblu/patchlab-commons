# Impact and measurement

PatchLab Commons should be judged by verified use, not by repository volume or promotional metrics.

## Primary measures

- external repositories that run PatchLab on real changes;
- Patch Passports generated;
- patches accepted upstream;
- unsafe changes blocked before merge;
- review findings confirmed as useful;
- false-positive rate per rule;
- median maintainer review time;
- new contributors who complete a patch laboratory.

## Evidence rules

Public impact reports must:

- distinguish attempted, completed, accepted, and merged patches;
- exclude synthetic demo runs from adoption totals;
- identify the measurement period;
- document missing data;
- preserve user and security privacy;
- avoid purchased stars, fake downloads, or automated spam.

## Pilot design

A first pilot can compare two contribution flows:

1. a normal public issue;
2. the same class of issue with a PatchLab reproduction and passport requirement.

Measure completion, test quality, scope violations, review cycles, and maintainer time.
